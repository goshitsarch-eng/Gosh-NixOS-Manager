# Linux Flutter migration audit

## Scope and evidence

Target: Linux desktop and Linux Flatpak only, per the user's scope correction. Windows and macOS are excluded. Existing application identity, NixOS configuration workflows, templates, JSON state, and useful behavior must be preserved. Flutter/Dart will replace the libcosmic presentation layer; Rust remains appropriate for Nix generation, parsing, validation, and privileged host operations.

Reference revision: `9da882af12c0bf41d198039380a665f6896efcc0`.

The reference architecture and evidence columns record the audit performed before implementation. WORKING means an existing automated check supported that reference behavior; PARTIAL records a limitation; UNKNOWN records missing runtime evidence. The Migration column and final validation section describe the implemented Flutter rewrite and its current verification. Real NixOS and real-desktop release gates remain open.

## Existing architecture

- Rust workspace, edition 2021, declared MSRV 1.93. No Flutter project or Dart sources exist in the reference tree.
- `crates/common`: serializable catalogs, request/response DTOs, system/configuration models, Nix generation, input validation. Already independent of the GUI toolkit.
- `crates/gui`: libcosmic/iced desktop shell, winit X11/Wayland, wgpu rendering, Fluent English strings, state reducer, native effects and helper process client. libcosmic is a Git dependency pinned to revision `7cc116803b18d7b888eb511b009f775f036c3da7`.
- `crates/helper`: unprivileged-to-privileged boundary through a separate executable and JSON lines over stdin/stdout. Handles managed files, rebuild, generations, maintenance. Entry point: `crates/helper/src/main.rs`.
- `crates/fake-helper`: JSONL test double, scripted replies, never writes `/etc/nixos`.
- GUI entry: `crates/gui/src/main.rs`. `AppModel` in `app.rs` owns window/presentation and selection state. `core/apply.rs` maps messages into intents. `app.rs::intents_to_task` executes effects. It is not a toolkit-independent core: model/messages include cosmic types, localized strings and visual intents.
- Application opens at 1000x700, minimum 640x480. Eleven sidebar pages, View menu with About and Refresh, refresh toolbar control. Ctrl+Q quits; Ctrl+R/F5 re-probe host/GPU. Escape closes context UI/dialogs. Single-instance mode is deliberately disabled.
- No database, project/document format, general import/export UI, undo/redo system or arbitrary file drag/drop was found. Do not invent these as parity requirements.

## Formats and persistence

- Helper wire format: Serde externally tagged with `type` and `payload`; one JSON record per line. Requests/responses in `common/src/ipc.rs`, including compatibility defaults for hardware and WireGuard fields and rollback activation.
- Managed state: `/etc/nixos/nixos-toolkit/state/state.json`, `AppState` fields from common IPC. UI-only expanders are not persisted. State is written after successful non-dry-build apply.
- Managed generated Nix: `state/selected.nix`, optional state snippets, profiles and bundles under `/etc/nixos/nixos-toolkit`. User adds the import to classic config or flake modules manually. Existing user configuration is not automatically edited.
- UI theme: `$XDG_CONFIG_HOME/nixos-toolkit/preferences.json`, `{"color_scheme":"system|light|dark"}`; fallback reads cosmic-config. Flutter must retain this compatibility. Flatpak XDG locations are sandbox-specific and must not silently lose settings.
- Templates: `nix/templates/profiles`, `nix/templates/bundles`; configured with `NIXOS_TOOLKIT_TEMPLATES_DIR`. Generated legacy bundle reconstruction is line-oriented, not a complete Nix parser.
- Known nonfree catalog attributes trigger managed `unfree.nix`; this is not universal `meta.unfree` detection.

## Linux assumptions and processes

NixOS semantics are the product's purpose and remain explicit Linux host integrations. Core generation should work without a NixOS host. Relevant processes: `pkexec`, `flatpak-spawn`, `lspci`, `hostname`, `nixos-rebuild`, `nix-env`, `switch-to-configuration`, allowlisted Nix maintenance commands, and `du`. Paths include `/etc/NIXOS`, `/etc/nixos`, `/nix/store`, `/nix/var/nix/profiles/system`, `/run/current-system/sw/bin`. Use argv-based launches, explicit capability results and narrowly scoped adapters. Do not expose arbitrary shell execution to Flutter or run the UI as root.

No application networking engine was found. Network activity is host tools updating Nix inputs and user-triggered external links; build dependency downloads are separate.

## Packaging and CI

- Flake packages: GUI, helper, templates and full; dev shell uses rust-overlay stable.latest, not exact workspace MSRV. NixOS module installs helper/polkit integration.
- Existing Flatpak manifest: Freedesktop 25.08, rust-stable SDK extension, GUI only. Allows Wayland/fallback X11, IPC, DRI, org.freedesktop.Flatpak host bridge, `/etc/NIXOS:ro`. Does not grant blanket host filesystem, network or all devices. Templates installed under `/app/share/nixos-toolkit/templates`.
- Flatpak host helper discovery is explicit; missing helper keeps local preview/preferences usable and disables privileged actions. Flutter migration must retain this behavior and use portals for appropriate file/URI integration.
- GitHub CI runs Cargo build/clippy/tests and Nix fmt/audit. Flatpak build/smoke is manual-dispatch only. Existing CI has no Dart/Flutter/bridge checks or Flutter releases.
- `scripts/verify.sh` includes Flatpak verification; it is not an appropriate default before SDK/runtime and sandbox support are established.

## Findings to resolve before migration parity

1. Confirmed source defect: `parse_package_input("] [")` slices with start greater than end and can panic. Mixed comma/newline/space inputs also take mutually exclusive parser branches and can discard valid tokens. Add Rust regression cases when extracting the parser.
2. WireGuard toggle disabling removes its listen port even when that UDP port was already explicitly user-selected. Track automatic versus manual ownership; do not silently delete unrelated firewall choices.
3. Missing profile template is omitted by local preview but apply generates a fallback. Use one core rendering policy for both operations.
4. Preference saves use direct `fs::write`, allowing truncation on interrupted writes; malformed JSON silently falls back. Migration should preserve recoverability with atomic writes and clear diagnostics where useful.
5. Helper oversized-line handling bounds the initial buffer, then allocates an unbounded `read_until` discard buffer. Discard oversized input without growing memory. This requires a backend coding change, not a setup workaround.
6. Hostname validation accepts leading/trailing hyphens and all-hyphen labels; input safety and valid hostnames are separate requirements. Review domain validation with compatibility fixtures.
7. Cancellation and UI dirty-state behavior need real host/process-tree testing. Do not infer successful rollback from GUI cancellation.
8. English-only Fluent/catalog strings, no persisted window geometry, no existing complete end-to-end visual suite. Test focus, resize, light/dark/system and disabled controls during Flutter implementation.

## Implemented Linux architecture

Flutter/Dart owns widgets, responsive desktop shell, page navigation, Actions/Shortcuts, focus/semantics, dialogs, presentation drafts, progress/log display, window lifecycle and straightforward theme preferences. Start with ChangeNotifier/ValueNotifier and scoped immutable presentation models; choose additional state packages only if complexity warrants them.

Rust common/core owns catalogs, configuration DTOs, parsing/classification, validation, deterministic preview generation and nontrivial compatibility/reconstruction. Keep the existing privileged helper as a distinct host process; do not put privileged mutation inside the Flutter-loaded library. Extract useful domain rules from the current GUI without importing libcosmic into the core.

Direct Dart FFI was selected for six coarse bounded value operations: bootstrap catalogs/defaults, host capabilities, parse/classify packages, validate, aggregate preview and profile preview. A generator would add generated DTO/handle machinery unused by this API. Dart dispatches calls in worker isolates and translates typed errors; Rust owns returned strings and frees them through its second exported symbol. No widget state or opaque Rust object graph crosses the boundary. See ARCHITECTURE.md for ownership, async and build details.

Flutter is now the canonical native release, flake default GUI and CI frontend. The former GUI remains an explicit reference package; its packaging manifest is named `reference-libcosmic.yml`. Removal awaits real NixOS parity; it is retained as a comparison reference.

## Remaining release gates and explicit differences

Real NixOS apply/dry-build/activation, authenticated cancellation of the root helper and descendants, generations and maintenance require a NixOS host. Hardware graphics, browser/file-manager portals, screen-reader/keyboard-only desktop QA and actual system theme notifications still require a real desktop. The nested Wayland and clipboard checks establish their tested compositor behavior. ARM64 is configured but untested. These limitations prevent a claim that the migration is release-complete.

NVIDIA selection adds “Keep existing” instead of silently selecting a proprietary driver merely because a GPU is detected. This preserves user configuration and prevents unintended writes. Theme no longer writes a cosmic mirror: Flutter has one canonical preference file, but reads the old mirror when JSON is absent. The old GUI has no useful drag/drop, notifications, document file dialogs, search/database or printing workflow to port; service Printing remains the existing CUPS configuration toggle. No unrelated application features or other OS frontends were introduced.

- Reusable setup rerun after the rewrite passed, including Rust workspace build and Flutter debug bundle. It also handles the older saved reference commit without modifying source. The current rewrite is uncommitted; snapshot/fresh-task restoration is not independently verified. Repository discovery found the single project checkout, SDK/reference tooling repositories, Cargo dependency/submodule caches and an empty sandbox mountpoint at `/workspace/.git`; tooling and caches are not project membership.
